# 信箱怎么用

> **给每个参与者配一个信箱，专门给别的桌往里扔东西；信箱对主人是只读的。**
>
> 这是整套东西里**最反直觉、也最有用**的一条规矩。

---

## 一、它解决什么问题

**老做法**：把东西放在自己家，然后叫对方来拿。

**为什么那是错的**：

```
❌ "交付"变成了"别人来读写我的目录"
     ├─ 耦合：我一改名，对方的指针就烂
     └─ 而且这是"跨目录写"的唯一起因
```

**新做法**：

```
✅ 直接写进对方的信箱  ⇒  所有权当场转移
```

**就像真信箱**：它是对方的，**但装在楼门口，不在对方家里** ——
所以**邮递员不用进别人家**。

---

## 二、权限（**这条是信箱的命根子**）

| 谁 | 往里放 | 读里面 |
|---|---|---|
| **别的桌** | ✅ **只能放** | ❌ **不许读** |
| **信箱主人** | ❌ **不许往里放** | ✅ **只读** |

**两条都重要**：

| 规矩 | 不这么定会怎样 |
|---|---|
| **"别人不许读"** | 否则共享目录里就多了一条"翻别人收件箱"的后门 |
| **"主人不许往里放"** | 否则信箱会变成主人的**第二个工作区** ⇒ "同一事实只有一个权威存放处"就破了 |

**放错了怎么办**：**再放一份更正 + 说一声**。**不要回头去改** —— 它已经不是你的了。

---

## 三、命名

```
来自<发件方>-<类型>-<主题>-<日期>
```

| 段 | 例 |
|---|---|
| 发件方 | `01` / `02` / `用户` |
| 类型 | `委托` / `执行报告` / `便条` / `提议` / `答复` |
| 主题 | 中文，说清是什么 |
| 日期 | `20260930`（日期做后缀） |

**例**：

```
00-通用\信箱\02\
├─ 来自01-委托-窗口性能问题-20260928.md
└─ 来自用户-便条-这个方向先停一下-20260930.md
```

**⚠️ 发件方那一段不能省** —— 信箱里会有多个来源，少了它就不知道是谁给的。

---

## 四、⭐ 投递单 ≠ 信箱（**依赖是单向的**）

| | 谁依赖谁 |
|---|---|
| **信箱** | **必须依赖投递** —— 往信箱放了东西，**就必须发一张单子告诉对方**（否则它不知道） |
| **投递** | ✅ **不依赖信箱** —— **单子是指针型的：一句话 + 指一个地方**（那地方可以是信箱，也可以是任何已有的文件） |

**⇒ 判据**：

> **能在一张单子里一句话说清的事，就直接在单子里说 —— 不要走信箱。**
> **信箱是给"有附件、要留档、内容长、要来回几轮"的那种协作的。**

⚠️ **别把这句读成"单子可以不带指针"** —— 工具里 **`ptr` 是必填的**：
单子**永远**要指一个**已存在**的地方（哪怕只是"指回原来那张单子"）。
**"一句话说清"说的是"别把正文写成一篇文档"，不是"可以不指地方"。**

---

## 五、为什么"信"和"文档"要分开对待

这是**反耦合规矩**的核心，值得单独说：

| | **信** | **文档** |
|---|---|---|
| 寿命 | **一次性的** | **长命的** |
| 对象 | **明确**（就给你） | 不明确（谁都可能读） |
| 里面能有**别人的路径**吗 | ✅ **能** | ⛔ **不能** |

**理由**：

> **文档是长命的** ⇒ 里面的路径**对方一改名就烂**。
> **信是一次性的** ⇒ 它过时了也没关系（它本来就只服务于那一次）。

**一句话版本**：**信是一次性的，文档是长命的。**

---

## 六、⭐ 搬家测试（动手搬东西之前必做）

> **"那张桌明天整个改名 / 搬家 / 归档，我这边会有东西坏掉吗？"**
> **会 ⇒ 你耦合了** —— 去把那份依赖**换成"信"**。

**⚠️ 搬家的那一方要把话说到位**：**要么把引用改对，要么发一张单子让对方自己改。**
⛔ **不要用"在老位置留个指路牌"糊过去** —— 那只会把办公区弄脏。

**实测代价**：原本只是想把两个收件目录搬个家，
**全办公室有 82 处引用要跟着动**。**⇒ 耦合就是这么长出来的，而且它按平方涨。**
